# Repository Structure Guide

This document explains the organization of the Congressional Generational Analysis project after the cleanup and reorganization.

## Directory Overview

```
congress_project/
├── api/                         # Production serverless functions (Vercel)
├── scripts/                     # Local data processing utilities
├── notebooks/                   # Jupyter notebooks for analysis
├── data/                        # Generated CSV files (git-ignored)
├── visualizations/              # Static HTML visualizations
├── congress_api_client.py       # API client (for Vercel imports)
├── congress_photo_api.py        # Photo API client (for Vercel imports)
├── vercel.json                  # Vercel configuration
├── requirements.txt             # Python dependencies
├── DEPLOYMENT.md                # Deployment guide
├── README.md                    # Main documentation
└── STRUCTURE.md                 # This file
```

## Detailed Directory Descriptions

### Root-Level API Client Files

**Important:** These files exist in both the root AND `/scripts/` directory:

- `congress_api_client.py` - Required in root for Vercel serverless functions to import
- `congress_photo_api.py` - Required in root for Vercel serverless functions to import

The copies in `/scripts/` are used for local development and analysis. The copies in the root are necessary for Vercel's serverless function imports to work properly.

### `/api/` - Serverless Functions

Production endpoints deployed to Vercel. These are the only Python files that run in production.

**Files:**

- `congress_data.py` - Main API endpoint for congressional data
- `member_photos.py` - API endpoint for member photos
- `test.py` - Testing utilities for API endpoints

**Key Points:**

- These files fetch data directly from Congress.gov API
- They do NOT read from CSV files
- Responses are cached (1-6 hours depending on endpoint)
- Deployed automatically when merged to main branch
- Import `congress_api_client.py` and `congress_photo_api.py` from the project root

### `/scripts/` - Local Utilities

Python scripts for local data processing and analysis. Run these on your machine, not in production.

**Files:**

- `python_analyzer.py` - Main analysis script, generates CSV files in `data/`
- `congress_api_client.py` - Wrapper for Congress.gov API
- `congress_photo_api.py` - Photo fetching utilities
- `congress_photo_fetcher.py` - Enhanced photo data processor
- `generate_api_charts.py` - Creates Altair visualizations that load from API

**Usage:**

```bash
cd scripts
export CONGRESS_API_KEY="your_key"
python python_analyzer.py
```

**Key Points:**

- All output paths use relative paths (`../data/`, `../visualizations/`)
- Run from the `scripts/` directory
- Generated files go to `data/` and `visualizations/`

### `/notebooks/` - Jupyter Notebooks

Interactive notebooks for exploratory analysis and visualization prototyping.

**Files:**

- `congress_eda.ipynb` - Exploratory data analysis
- `congress_graphs.ipynb` - Chart generation and refinement

**Usage:**

```bash
cd notebooks
jupyter notebook
```

**Key Points:**

- All file paths use relative references (`../data/congress_members_with_photos.csv`)
- Great for prototyping before moving code to scripts
- Visualizations can be saved to `../visualizations/`

### `/data/` - Generated Data Files

CSV files generated by scripts for local analysis.

**Files (generated, git-ignored):**

- `congress_generational_summary.csv` - Summary by generation
- `congress_generational_topics.csv` - Bill topics by generation
- `congress_individual_members.csv` - Individual member details
- `congress_members_with_photos.csv` - Members with photo URLs

**Key Points:**

- Files are git-ignored (except `.gitkeep`)
- Generated by running `python_analyzer.py` and `congress_photo_fetcher.py`
- NOT used by production API (API fetches live data)
- Useful for local analysis in notebooks

### `/visualizations/` - HTML Visualizations

Static HTML files with Altair/Vega-Lite visualizations.

**Types:**

1. **Static data** - Embed data directly in HTML
2. **API-powered** - Load data dynamically from Vercel API

**Key Points:**

- Can be hosted on GitHub Pages
- API-powered charts always show current data
- Embeddable in WordPress via iframes

## File Path Conventions

### In Scripts (`/scripts/`)

```python
# Write to data directory
df.to_csv("../data/output.csv")

# Save visualization
chart.save("../visualizations/chart.html")
```

### In Notebooks (`/notebooks/`)

```python
# Read from data directory
df = pd.read_csv("../data/input.csv")

# Save visualization
chart.save("../visualizations/chart.html")
```

### In API Functions (`/api/`)

```python
# No file I/O - fetch data directly from Congress.gov API
response = requests.get("https://api.congress.gov/v3/member")
```

## Workflow Examples

### Local Analysis Workflow

```bash
# 1. Generate data
cd scripts
export CONGRESS_API_KEY="your_key"
python python_analyzer.py

# 2. Enhance with photos
python congress_photo_fetcher.py

# 3. Explore in notebook
cd ../notebooks
jupyter notebook congress_eda.ipynb
```

### Production Deployment Workflow

```bash
# 1. Update API code in /api/ if needed
# 2. Test locally
vercel dev

# 3. Deploy to production
vercel --prod

# 4. Generate API-powered visualizations
cd scripts
python generate_api_charts.py

# 5. Commit and push visualizations
git add ../visualizations/*.html
git commit -m "Update visualizations"
git push origin main
```

## Migration Notes

### What Changed

- Scripts moved to `/scripts/`
- Notebooks moved to `/notebooks/`
- CSV files moved to `/data/`
- HTML files moved to `/visualizations/`
- All file paths updated with relative references
- `.gitignore` updated to exclude data files

### What Stayed the Same

- `/api/` functions unchanged (already organized)
- `vercel.json` and `requirements.txt` in root
- API endpoints and URLs unchanged

### Breaking Changes

If you have local scripts or notebooks not in the repo, update your paths:

- `congress_members.csv` → `data/congress_members.csv` (from project root)
- `congress_members.csv` → `../data/congress_members.csv` (from scripts/ or notebooks/)

## Best Practices

### Do

- Run analysis scripts from the `scripts/` directory
- Use relative paths (`../data/`, `../visualizations/`)
- Keep data files git-ignored
- Generate fresh data before analysis
- Test API endpoints locally with `vercel dev`

### Don't

- Don't commit CSV files to git
- Don't use absolute paths in code
- Don't run scripts from the project root (use `cd scripts` first)
- Don't manually edit generated CSV files
- Don't use CSV files in production API code
